Налагодження (debugging) — процес пошуку і виправлення помилок у коді. Браузерні DevTools надають повноцінний дебаґер з точками зупинки, переглядом стану і крокове виконання. Навичка ефективного використання дебаґера скорочує час пошуку помилок у рази.

Відкриття та панель Sources

Відкрийте DevTools через F12 або Ctrl+Shift+I (Windows/Linux) / Cmd+Option+I (macOS) і перейдіть на вкладку Sources. Ліва панель показує файлову структуру. Центральна — вихідний код. Права — інструменти дебаґінгу.

Точки зупинки (Breakpoints)

Клік на номер рядка встановлює точку зупинки — позначку де виконання призупиниться. При зупинці стають доступні:

  • Scope — всі змінні поточного, замикаючих і глобального scope
  • Call Stack — ланцюг викликів від поточної функції до точки входу
  • Watch — довільні вирази, обчислювані в поточному контексті
JavaScript
function processOrder(items) {
  const subtotal = items.reduce((sum, item) => sum + item.price, 0); // ← breakpoint тут
  const tax      = subtotal * 0.2;
  const total    = subtotal + tax;
  return { subtotal, tax, total };
}

// При зупинці на рядку з reduce:
// Scope показує: items = [...], sum = 0 (перша ітерація)
// Call Stack показує: processOrder → (caller)

Типи точок зупинки

Умовні точки зупинки

Правий клік на точку зупинки → «Edit breakpoint» — зупиняється лише якщо вираз true. Незамінні для налагодження циклів із тисячами ітерацій.

JavaScript
// Умова для точки зупинки:
// i === 999 && data.length === 0
// Зупиниться лише на 999-й ітерації з порожнім data

for (let i = 0; i < 10000; i++) {
  processChunk(data, i); // ← умовний breakpoint
}

Logpoints

Правий клік на рядок → «Add logpoint» — виводить вираз у консоль без зупинки виконання. Еквівалент console.log без зміни коду.

DOM breakpoints

В панелі Elements: правий клік на елемент → «Break on» → вибір типу:

  • Subtree modifications — зупиняє при зміні дочірніх елементів
  • Attribute modifications — при зміні атрибутів
  • Node removal — при видаленні елемента

Event listener breakpoints

Права панель Sources → «Event Listener Breakpoints» — зупинка при будь-якій події браузера (click, XHR, timer тощо) без прив'язки до конкретного рядка.

Оператор debugger

JavaScript
function calculateDiscount(price, code) {
  debugger; // зупиниться тут якщо DevTools відкриті

  const validCodes = { 'SAVE10': 0.10, 'SAVE20': 0.20 };
  const rate = validCodes[code];
  if (!rate) return price;
  return price * (1 - rate);
}

// У продакшені: DevTools закриті → debugger ігнорується
// Видаляйте debugger перед комітом (або налаштуйте ESLint no-debugger)

Watch expressions

У панелі Watch (права колонка Sources) можна додати вирази, що обчислюватимуться в поточному контексті при кожній зупинці. Корисно для відстеження складних умов.

JavaScript
// Приклади виразів для Watch:
// items.length
// total > budget
// JSON.stringify(config)
// user?.role === 'admin'
// items.filter(i => i.price > 100).length

Call Stack аналіз

Call Stack показує послідовність викликів, що призвела до поточної точки. Клік на кадр — перехід до відповідного рядка і контексту. Це дозволяє відстежити звідки прийшли дані, що спричинили помилку.

JavaScript
// Якщо в Stack бачимо: processPayment → validateCard → formatNumber
// Клікаємо на validateCard — DevTools показує контекст того виклику
// Можна перевірити значення card, amount у той момент

Стратегії пошуку помилок

Divide and conquer

Ізолюйте проблему: розбийте код на половини і перевіряйте яка половина містить помилку. Повторюйте до знаходження мінімального відтворюючого прикладу.

Поясніть код вголос

Пояснення коду рядок за рядком (навіть відсутній співрозмовник підійде) часто виявляє помилку — мозок по-іншому обробляє вербальний опис.

Console tracing

JavaScript
// console.trace() — виводить поточний call stack
function processData(data) {
  console.trace('processData called');
  return transform(data);
}

// console.time/timeEnd — пошук вузьких місць
console.time('heavy-operation');
heavyOperation();
console.timeEnd('heavy-operation'); // "heavy-operation: 142ms"

// console.count — кількість викликів
function render() {
  console.count('render'); // render: 1, render: 2...
}

Source maps

Bundler-и (Webpack, Vite, esbuild) компілюють і мінімізують код. Source maps дозволяють DevTools показувати оригінальний TypeScript/ES6+ код замість скомпільованого. Переконайтесь що devtools: 'source-map' увімкнено в конфігурації збірки.

Підсумок

  • Sources → клік на номер рядка → breakpoint. При зупинці доступні Scope, Call Stack, Watch.
  • Крокове виконання: F8 Resume, F10 Step over, F11 Step into, Shift+F11 Step out.
  • Умовні breakpoints — для циклів. Logpoints — замість console.log без зміни коду. DOM breakpoints — при мутаціях DOM.
  • debugger у коді — програмна точка зупинки. Видаляйте перед комітом.
  • Watch expressions — довільні вирази в поточному контексті. Call Stack — трасування ланцюга викликів.
  • Source maps — дебаґінг оригінального коду після компіляції.
