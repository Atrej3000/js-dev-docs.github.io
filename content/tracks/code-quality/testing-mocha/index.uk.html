Автоматичне тестування — виконання коду, що перевіряє правильність роботи іншого коду. Тест виявляє регресії: зміни, що зламали функціональність яка раніше працювала. Добре протестований код можна безпечно рефакторити.

Чому це важливо

Без тестів кожна зміна в коді потребує ручної перевірки всіх пов'язаних сценаріїв. Зі збільшенням кодової бази це стає неможливим. Тести дозволяють розробнику вносити зміни з впевненістю: якщо тести проходять — поведінка збережена.

Види тестів

  • Unit tests — тестують ізольовану функцію або модуль без зовнішніх залежностей.
  • Integration tests — тестують взаємодію кількох модулів.
  • End-to-end (E2E) tests — тестують повні сценарії користувача через браузер.

Mocha — тестовий фреймворк

Mocha надає структуру для тестів: describe для групування, it для окремих тест-кейсів. Не містить assertion-бібліотеки — для перевірок використовують Chai, Node.js assert або інші.

bash
npm install --save-dev mocha chai
# package.json: "test": "mocha"

BDD синтаксис

JavaScript — pow.test.js
import { expect } from 'chai';
import { pow } from './pow.js';

// describe — група тестів (зазвичай один модуль або функція)
describe('pow', () => {

  // it — один тест-кейс: "щось має щось"
  it('повертає n у степені 1 як n', () => {
    expect(pow(3, 1)).to.equal(3);
    expect(pow(7, 1)).to.equal(7);
  });

  it('повертає n у степені 2 як n*n', () => {
    expect(pow(3, 2)).to.equal(9);
    expect(pow(4, 2)).to.equal(16);
  });

  it('повертає n у степені 3', () => {
    expect(pow(2, 3)).to.equal(8);
    expect(pow(3, 3)).to.equal(27);
  });

  it('кидає помилку для від\'ємного степеня', () => {
    expect(() => pow(2, -1)).to.throw(RangeError);
  });

});

Chai assertions

JavaScript
// Рівність
expect(result).to.equal(42);          // строга рівність ===
expect(result).to.deep.equal({a: 1}); // глибоке порівняння
expect(result).to.not.equal(0);

// Тип
expect(value).to.be.a('string');
expect(arr).to.be.an('array');
expect(fn).to.be.a('function');

// Булеве
expect(isActive).to.be.true;
expect(hasError).to.be.false;
expect(result).to.be.null;
expect(value).to.be.undefined;

// Числа
expect(score).to.be.above(0);
expect(score).to.be.below(100);
expect(score).to.be.within(0, 100);

// Рядки і масиви
expect(name).to.include('John');
expect(arr).to.include(42);
expect(arr).to.have.lengthOf(3);

// Винятки
expect(() => fn(null)).to.throw(TypeError);
expect(() => fn(-1)).to.throw(RangeError, 'must be positive');

Hooks: beforeEach і afterEach

JavaScript
describe('UserService', () => {
  let service;
  let mockDb;

  // Виконується перед кожним it
  beforeEach(() => {
    mockDb  = createMockDatabase();
    service = new UserService(mockDb);
  });

  // Виконується після кожного it — очищення
  afterEach(() => {
    mockDb.clear();
  });

  // before/after — один раз для всього describe
  before(() => { /* ініціалізація дорогого ресурсу */ });
  after(()  => { /* звільнення ресурсу */ });

  it('створює користувача', () => {
    const user = service.create({ name: 'Test' });
    expect(user.id).to.be.a('number');
  });

  it('знаходить користувача за id', () => {
    const created = service.create({ name: 'Test' });
    const found   = service.findById(created.id);
    expect(found).to.deep.equal(created);
  });
});

Асинхронні тести

JavaScript
describe('fetchUser', () => {

  // async/await — найзручніший спосіб
  it('повертає дані користувача', async () => {
    const user = await fetchUser(1);
    expect(user.id).to.equal(1);
    expect(user).to.have.property('name');
  });

  it('відхиляє проміс при неіснуючому id', async () => {
    try {
      await fetchUser(99999);
      expect.fail('Мав кинути помилку'); // якщо дійшли сюди — тест провалений
    } catch (err) {
      expect(err).to.be.instanceOf(NotFoundError);
    }
  });

  // Або через chai-as-promised
  it('відхиляє проміс', () => {
    return expect(fetchUser(99999)).to.be.rejectedWith(NotFoundError);
  });
});

TDD: Test-Driven Development

Підхід де тест пишеться до реалізації. Цикл: Red → Green → Refactor.

  1. Red: Напишіть тест для нової функції — він має не проходити.
  2. Green: Напишіть мінімальну реалізацію щоб тест пройшов.
  3. Refactor: Покращіть код зберігаючи проходження тестів.

Підсумок

  • describe — група тестів. it — один тест-кейс. Назви у форматі «що має що робити».
  • Chai expect: .equal, .deep.equal, .to.throw, .to.be.a.
  • beforeEach/afterEach — setup/teardown для кожного тесту.
  • Async тести: async/await у callback it.
  • TDD: Red → Green → Refactor.
  • Альтернативи Mocha: Jest (вбудовані assertions, mocking), Vitest (ES-modules, швидший).
