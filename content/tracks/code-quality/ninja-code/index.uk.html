«Ninja code» — неформальна назва практик, що роблять код надмірно стислим або хитрим. Такий код важко читати, тестувати і підтримувати. Ця стаття показує реальні антипатерни і принципи написання ясного коду.

Базові принципи

  • DRY (Don't Repeat Yourself) — уникайте дублювання логіки. Одне рішення в одному місці.
  • KISS (Keep It Simple) — простіше рішення краще складного, якщо воно вирішує задачу.
  • YAGNI (You Aren't Gonna Need It) — не додавайте функціонал «на майбутнє».
  • Single Responsibility — функція або клас повинні мати одну причину для зміни.

function calculateDiscount(user, order) {
  const rawDiscount = user.accountLevel * order.discountRate;
  if (rawDiscount > user.discountLimit) return user.maxDiscount;
  return rawDiscount;
}

function insertAtPosition(array, value, index) {
  const isEvenIndex = index % 2 === 0;
  const insertAt    = Math.floor(index / 2);

  if (isEvenIndex) {
    array.splice(insertAt, 0, value);
  } else {
    array.push(value);
  }
  return array;
}

function processOrder(order) {
  if (order) {
    if (order.user) {
      if (order.user.isActive) {
        if (order.items && order.items.length > 0) {
          return fulfill(order);
        }
      }
    }
  }
  return null;
}

// ПРАВИЛЬНО: guard clauses — ранній вихід
function processOrder(order) {
  if (!order)                               return null;
  if (!order.user)                          return null;
  if (!order.user.isActive)                 return null;
  if (!order.items || !order.items.length)  return null;

  return fulfill(order);
}

Підсумок

  • DRY, KISS, YAGNI, Single Responsibility — чотири принципи, що вирізняють ясний код.
  • Описові імена замість абревіатур. Однолітерні — лише для ітераторів і математики.
  • Магічні числа → іменовані константи.
  • Приховані побічні ефекти → явні функції з зрозумілими назвами.
  • Глибока вкладеність → guard clauses (ранній вихід).
  • Великі функції → декомпозиція за single responsibility.
