Стандарт оформлення (code style) — набір угод про форматування, іменування і структуру коду. Консистентний стиль знижує когнітивне навантаження при читанні і спрощує code review. У сучасних проектах форматування автоматизоване — розробник не думає про пробіли та дужки.

Чому це важливо

Код читають набагато частіше, ніж пишуть. Неоднорідне форматування ускладнює розрізнення структурно важливих змін від косметичних. Автоматизований стиль (Prettier + ESLint) усуває суперечки в команді і звільняє code review для змістовних обговорень.

Фігурні дужки

JavaScript
// Стиль K&R (рекомендований для JS): відкриваюча дужка на тому ж рядку
if (condition) {
  doSomething();
} else {
  doSomethingElse();
}

// Завжди фігурні дужки — навіть для одного рядка
// АНТИПАТЕРН:
if (condition)
  doSomething(); // небезпечно: легко зламати при додаванні рядка

// ПРАВИЛЬНО:
if (condition) {
  doSomething();
}

ESLint і Prettier

ESLint — статичний аналізатор, що виявляє логічні помилки і антипатерни. Prettier — автоформатувальник, що переписує код за єдиним стилем.

JSON — .eslintrc.json
{
  "env": { "browser": true, "es2024": true },
  "extends": ["eslint:recommended"],
  "rules": {
    "no-var":        "error",
    "prefer-const":  "error",
    "no-unused-vars":"warn",
    "no-console":    "warn",
    "eqeqeq":       ["error", "always"],
    "no-debugger":   "error"
  }
}
JSON — .prettierrc
{
  "semi": true,
  "singleQuote": true,
  "tabWidth": 2,
  "trailingComma": "es5",
  "printWidth": 80,
  "arrowParens": "avoid"
}

Популярні стайлгайди

  • Airbnb (eslint-config-airbnb) — найдетальніший, строгий. Стандарт у великих React-проектах.
  • Standard JS (eslint-config-standard) — без крапки з комою, мінімалістичний.
  • Google — схожий на Airbnb, менш поширений.
  • XO — суворий, з вбудованими TypeScript-правилами.
Практична рекомендація

Для нового проекту: eslint:recommended + Prettier + prefer-const, no-var, eqeqeq. Для TypeScript-проекту: @typescript-eslint/recommended. Налаштування «format on save» у VS Code автоматизує форматування.

Підсумок

  • Відступи: 2 пробіли (стандарт JS-спільноти). Консистентність важливіша за конкретний вибір.
  • Фігурні дужки завжди — навіть для однорядкових блоків.
  • Іменування: camelCase для змінних/функцій, PascalCase для класів, UPPER_SNAKE для примітивних констант.
  • Булеві: префікс is/has/can. Функції: дієслово + іменник.
  • ESLint — статичний аналіз, Prettier — форматування. Налаштовуйте обидва в кожному проекті.
