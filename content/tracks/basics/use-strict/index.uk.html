Директива "use strict" вмикає суворий режим виконання (strict mode), введений у ES5. Він перетворює мовчазні помилки JavaScript на явні винятки і забороняє деякі небезпечні конструкції.

Чому це важливо

JavaScript до ES5 мав поведінку «мовчати замість помилки»: присвоєння неоголошеній змінній, запис у read-only властивість, видалення невидаляємого — все це відбувалося без помилки. Strict mode перетворює ці тихі збої на TypeError або ReferenceError, що дозволяє знайти їх під час розробки, а не в продакшені.

Активація

Директива — це рядковий літерал "use strict" або 'use strict', що стоїть першим рядком скрипта або функції.

JavaScript
// Весь файл у strict mode
"use strict";

function processOrder(order) {
  // ...
}

// Тільки функція у strict mode (застарілий підхід для legacy-файлів)
function validate(data) {
  "use strict";
  // ...
}
Позиція директиви критична

Якщо перед "use strict" є будь-який виконуваний код (навіть порожній рядок не є проблемою, але інструкція — так), директива ігнорується. Вона повинна бути першою інструкцією.

Що змінює strict mode

1. Заборона неоголошених змінних

JavaScript
"use strict";

// sloppy mode: тихо створює глобальну змінну
// strict mode: ReferenceError
typoVariable = 42; // ReferenceError: typoVariable is not defined

// Правильно: завжди оголошувати
let typoVariable = 42;

2. Заборона запису у read-only властивості

JavaScript
"use strict";

const obj = {};
Object.defineProperty(obj, 'id', { value: 1, writable: false });

obj.id = 2; // TypeError: Cannot assign to read only property 'id'
// У sloppy mode це мовчки ігнорується

3. Заборона видалення невидаляємих властивостей

JavaScript
"use strict";

delete Object.prototype; // TypeError
// У sloppy mode повертає false без помилки

4. Заборона дублікатів параметрів

JavaScript
"use strict";

// SyntaxError: Duplicate parameter name not allowed in this context
function sum(a, a, b) { // ← дублікат параметра
  return a + b;
}
// У sloppy mode другий 'a' мовчки перекриває перший

5. this у функціях без контексту

JavaScript
"use strict";

function showThis() {
  console.log(this);
}

showThis();         // undefined (strict)
                    // globalThis (sloppy)

showThis.call(null); // null (strict)
                     // globalThis (sloppy)

6. Заборона зарезервованих слів

Strict mode забороняє використовувати як ідентифікатори слова, зарезервовані для майбутніх версій: implements, interface, let, package, private, protected, public, static, yield.

Модулі та класи — завжди strict

ES-модулі (type="module") та тіла класів виконуються у strict mode автоматично, незалежно від наявності директиви. У сучасному коді на модулях "use strict" надлишковий.

JavaScript
// type="module" → автоматично strict mode
// "use strict" тут надлишковий, але не шкідливий
export function processData(data) {
  undeclaredVar = 1; // ReferenceError без директиви
}

// Тіло класу — також завжди strict
class Service {
  process() {
    undeclaredVar = 1; // ReferenceError
  }
}

Транспілери та bundler

Babel, TypeScript (з target: ES5), esbuild та більшість bundler-ів за замовчуванням додають "use strict" до скомпільованого коду. Тому у TypeScript-проектах директива є автоматично.

Підсумок

  • "use strict" — директива ES5, що перетворює мовчазні помилки на явні винятки.
  • Повинна бути першою інструкцією файлу або функції.
  • Забороняє: неоголошені змінні, запис у read-only, дублікати параметрів, видалення невидаляємого.
  • Змінює значення this у функціях без контексту: undefined замість globalThis.
  • ES-модулі та тіла класів — завжди strict mode автоматично.
  • Завжди використовуйте strict mode у новому коді. У проектах на ES-модулях або TypeScript він вже активний.
