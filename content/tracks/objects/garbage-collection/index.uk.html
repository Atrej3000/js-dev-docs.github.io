Збирання сміття (garbage collection, GC) — автоматичне звільнення пам'яті від об'єктів, що більше не використовуються. JavaScript управляє пам'яттю автоматично: розробник не викликає free() як у C. Але розуміння принципів допомагає уникати витоків пам'яті.

Досяжність (Reachability)

Основний принцип: об'єкт зберігається в пам'яті, якщо він досяжний — тобто до нього можна дістатись з кореневих посилань.

Корені — завжди досяжні:

  • Глобальний об'єкт (globalThis / window)
  • Поточний стек викликів (локальні змінні і параметри всіх активних функцій)
  • Внутрішні посилання рушія
JavaScript
// Об'єкт досяжний через змінну user
let user = { name: 'Олена' };

// Переносимо посилання в admin
let admin = user;

// Обнуляємо user — але об'єкт ще досяжний через admin
user = null;
console.log(admin.name); // "Олена" — об'єкт живий

// Обнуляємо admin — більше немає посилань → об'єкт стане недосяжним
admin = null;
// { name: 'Олена' } буде зібраний GC

Алгоритм mark-and-sweep

V8 (і більшість сучасних рушіїв) використовує варіант tri-color mark-and-sweep:

  1. Mark: починаючи з коренів, рекурсивно позначає всі досяжні об'єкти.
  2. Sweep: проходить по пам'яті і звільняє непозначені (недосяжні) об'єкти.
  3. Compact: дефрагментує пам'ять (опціонально).

V8 поділяє heap на покоління — молоді об'єкти (short-lived) збираються частіше і швидше. Більшість об'єктів живе дуже короткий час — ця евристика значно підвищує ефективність GC.

Типові витоки пам'яті

1. Випадкові глобальні змінні

JavaScript
// Без "use strict": забута var → глобальна змінна
function process() {
  data = fetchLargeDataset(); // без var/let/const → window.data
  // data ніколи не буде зібрана до перезавантаження сторінки
}
// РІШЕННЯ: завжди use strict + явне оголошення змінних

2. Незвільнені event listeners

JavaScript
// ВИТІК: listener утримує замикання з великими даними
function setupComponent() {
  const largeData = new Array(1_000_000).fill(0);

  document.addEventListener('click', () => {
    console.log(largeData.length); // largeData у замиканні
  });
  // Listener і largeData живуть поки document живий
}

// РІШЕННЯ: видаляти listener при demount
function setupComponent() {
  const largeData = new Array(1_000_000).fill(0);

  const handler = () => console.log(largeData.length);
  document.addEventListener('click', handler);

  // Повертаємо функцію cleanup
  return () => document.removeEventListener('click', handler);
}

3. Замикання що утримують більше ніж потрібно

JavaScript
// ВИТІК: замикання утримує весь масив заради одного значення
function createSummary(items) {
  // items — великий масив
  const total = items.reduce((s, i) => s + i.price, 0);

  return function getSummary() {
    return `Total: ${total}`; // утримує total, але items залишається в scope
  };
}

// V8 оптимізує це, але явне скорочення — надійніше
function createSummaryFixed(items) {
  const total = items.reduce((s, i) => s + i.price, 0);
  // items більше не потрібен — залишаємо тільки total
  return () => `Total: ${total}`;
  // items виходить зі scope після завершення createSummaryFixed
}

4. Від'єднані DOM-вузли

JavaScript
// ВИТІК: посилання на видалений DOM-елемент
const elements = [];

function addRow() {
  const row = document.createElement('tr');
  document.querySelector('table').appendChild(row);
  elements.push(row); // тримаємо посилання
}

function clearTable() {
  document.querySelector('table').innerHTML = ''; // видаляємо з DOM
  // elements ще тримає посилання → DOM-вузли не зібрані

  // РІШЕННЯ:
  elements.length = 0; // очищаємо масив після видалення з DOM
}

WeakRef і FinalizationRegistry

WeakRef дозволяє зберігати «слабке» посилання — воно не перешкоджає збиранню сміття.

JavaScript
let target = { data: new Array(10_000).fill(0) };
const weakRef = new WeakRef(target);

// Поки target живий
console.log(weakRef.deref()?.data.length); // 10000

target = null; // знімаємо сильне посилання
// GC може зібрати об'єкт у будь-який момент

// Після збирання
console.log(weakRef.deref()); // undefined — об'єкт зібраний

// FinalizationRegistry — callback при зборі об'єкта (для логування/cleanup)
const registry = new FinalizationRegistry(heldValue => {
  console.log(`Зібрано: ${heldValue}`);
});
registry.register(target, 'my-object');

Підсумок

  • GC звільняє об'єкти що стали недосяжними з кореневих посилань.
  • Алгоритм mark-and-sweep: позначає досяжні → звільняє непозначені.
  • Витоки: глобальні змінні без оголошення, незвільнені listeners, від'єднані DOM-вузли в масивах/Map.
  • Завжди видаляйте listeners при знищенні компонента (removeEventListener).
  • WeakRef — слабке посилання що не перешкоджає GC. WeakMap/WeakSet — колекції зі слабкими ключами.
