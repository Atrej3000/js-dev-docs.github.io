Обробка помилок у Promise має свою специфіку: помилки "тихо" проходять по ланцюжку до першого .catch(). Важливо знати, де ставити .catch(), як відновлюватись після помилки і що робити з необробленими rejected Promise.

Неявне перехоплення

JavaScript
// throw всередині executor → rejected Promise
const p = new Promise((resolve, reject) => {
  throw new Error('executor error'); // еквівалентно reject(new Error(...))
});
p.catch(console.error); // Error: executor error

// throw всередині .then → передається в .catch
Promise.resolve('ok')
  .then(val => { throw new Error('then error'); })
  .catch(err => console.log('caught:', err.message)); // 'caught: then error'

Відновлення після помилки

JavaScript
// .catch може повернути значення — ланцюжок продовжується
Promise.reject(new Error('fail'))
  .catch(err => {
    console.log('handled:', err.message);
    return 'default value'; // відновлення
  })
  .then(val => console.log('continuing with:', val)); // 'default value'

// Якщо .catch кидає — наступний .catch перехоплює
Promise.reject(new Error('first'))
  .catch(err => { throw new Error('second'); })
  .catch(err => console.log('final catch:', err.message)); // 'second'

Необроблені помилки

JavaScript
// Браузер: подія unhandledrejection
window.addEventListener('unhandledrejection', event => {
  console.error('Необроблено:', event.promise, event.reason);
  event.preventDefault(); // придушити стандартне попередження
});

// Node.js
process.on('unhandledRejection', (reason, promise) => {
  console.error('Необроблено:', reason);
  process.exit(1); // рекомендовано завершити процес
});

// Антипатерн: ковтання помилок
somePromise.catch(() => {}); // небезпечно — помилка зникає мовчки

Де ставити .catch()

JavaScript
// Варіант 1: один .catch в кінці — ловить все
step1()
  .then(step2)
  .then(step3)
  .catch(err => console.error('будь-який крок:', err));

// Варіант 2: .catch посередині для часткового відновлення
step1()
  .catch(err => fallback())  // якщо step1 провалився — запасний варіант
  .then(step2)
  .then(step3)
  .catch(err => console.error('step2 або step3:', err));

Золоте правило: кожен ланцюжок Promise, що виходить назовні функції, повинен мати .catch(). Якщо функція повертає Promise — відповідальність за .catch() переходить до споживача.

Підсумок

  • throw в executor або .then() → rejected Promise
  • .catch() що повертає значення — відновлює ланцюжок
  • Необроблені rejected Promise — критична помилка у production
  • Завжди є .catch() на кожному зовнішньому ланцюжку
