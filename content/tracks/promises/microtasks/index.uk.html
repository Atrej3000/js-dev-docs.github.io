Черга мікрозавдань (microtask queue) — вища пріоритетність, ніж macrotasks. Коли стек викликів порожніє, рушій спочатку виконує всі мікрозавдання, а потім бере наступний macrotask. Promise callback — це мікрозавдання.

Event loop і черги

JavaScript
// Порядок виконання
console.log('1 — sync');

setTimeout(() => console.log('2 — macrotask'), 0);

Promise.resolve()
  .then(() => console.log('3 — microtask'))
  .then(() => console.log('4 — microtask 2'));

console.log('5 — sync');

// Вивід:
// 1 — sync
// 5 — sync
// 3 — microtask       ← мікрозавдання до macrotask
// 4 — microtask 2     ← всі мікрозавдання до наступного macrotask
// 2 — macrotask

MessageChannelprocess.nextTick (Node.js, найвищий пріоритет)
JavaScript
// Схема event loop (спрощено):
// while(true) {
//   1. Виконати весь поточний стек викликів
//   2. Виконати ВСІ мікрозавдання (поки черга не порожня)
//   3. Якщо потрібен рендер — рендерити
//   4. Взяти одне macrotask → goto 1
// }

// Нескінченна рекурсія через мікрозавдання ЗАВИСНЕ event loop!
function badRecursion() {
  return Promise.resolve().then(badRecursion); // заблокує браузер
}

// Для довгих операцій — використовуй setTimeout (дає браузеру "дихнути")

queueMicrotask()

JavaScript
// Явне додавання мікрозавдання
queueMicrotask(() => {
  console.log('це мікрозавдання');
});

// Практичний кейс: відкладити виконання до кінця поточного "тіку"
// але перед наступним macrotask
function notifyAsync(callback) {
  queueMicrotask(callback);
}

Якщо мікрозавдання генерують нові мікрозавдання нескінченно — event loop зависне, і UI не оновиться. Довгі обчислення поділяй через setTimeout(chunk, 0), щоб давати браузеру рендерити.

Підсумок

  • Після кожного macrotask виконуються ВСІ мікрозавдання (Promise callbacks)
  • Пріоритет: process.nextTick > мікрозавдання > macrotask
  • queueMicrotask(fn) — явне додавання мікрозавдання
  • Ніколи не блокуй мікрочергу нескінченною рекурсією
