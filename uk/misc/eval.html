eval

ПросунутийРізне~ 8 хв

eval() виконує рядок коду як JavaScript у поточному scope. Це надзвичайно потужний і надзвичайно небезпечний інструмент. У сучасному JS практично завжди є кращі альтернативи.

Базова поведінка

JavaScript
// eval виконує рядок як JS
eval('1 + 1');         // 2
eval('console.log("hello")'); // виводить "hello"

const x = 10;
eval('x + 5');         // 15 — доступ до локального scope

// eval може створювати змінні у поточному scope (non-strict)
eval('var y = 42');
console.log(y);        // 42 — y існує у навколишньому scope!

// У strict mode — eval має власний scope
'use strict';
eval('var z = 1');
// console.log(z);     // ReferenceError — z не в outer scope

Прямий та непрямий eval

JavaScript
const x = 'global';

function test() {
  const x = 'local';

  // Прямий eval — бачить локальний scope
  eval('console.log(x)');  // 'local'

  // Непрямий eval — тільки глобальний scope
  const indirectEval = eval;
  indirectEval('console.log(x)'); // 'global'

  // Інший запис непрямого eval
  (0, eval)('console.log(x)');    // 'global'
}
test();

Ніколи не передавай у eval() дані від користувача — це пряма вразливість XSS та Code Injection. Атакуючий може виконати будь-який код у контексті твого застосунку.

Проблеми з продуктивністю

JavaScript
// Рушій не може оптимізувати функцію, що містить eval
// — невідомо, які змінні будуть змінені
function bad() {
  const a = 1, b = 2;
  eval(someExternalCode); // оптимізатор відключається для всієї функції
  return a + b;
}

// Навіть без виклику — сам факт наявності eval у функції
// перешкоджає V8 оптимізувати hidden classes

Альтернативи eval

JavaScript
// 1. Замість eval для обчислення формул — Function constructor
const expr = 'a * b + c';
const fn = new Function('a', 'b', 'c', `return ${expr}`);
fn(2, 3, 4); // 10

// 2. Замість eval для парсингу JSON — JSON.parse
// eval('(' + jsonStr + ')') — НІКОЛИ
JSON.parse(jsonStr); // безпечно

// 3. Замість eval для доступу до властивостей — bracket notation
const propName = 'name';
eval(`obj.${propName}`);  // погано
obj[propName];             // добре

// 4. Замість eval для шаблонів — template literals
const tmpl = 'Hello, ${name}!';
eval('`' + tmpl + '`');   // погано і небезпечно
tmpl.replace('${name}', actualName); // або Handlebars/mustache

Підсумок

  • eval() виконує рядок у поточному (прямий) або глобальному (непрямий) scope
  • Вразливий до XSS — ніколи не використовувати з user input
  • Вимикає JIT-оптимізації для всієї функції
  • Заблокований CSP у більшості production-середовищ
  • Альтернативи: JSON.parse, bracket notation, new Function, template engines
