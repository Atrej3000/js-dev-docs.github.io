Вбудовані прототипи

СереднійПрототипи, наслідування~ 10 хв

Вбудовані об'єкти JavaScript (Array, String, Object) мають свої прotototype-ланцюги. Всі вони зрештою успадковують від Object.prototype. Розуміння цієї ієрархії пояснює звідки беруться методи на масивах, рядках і числах.

Ієрархія прotototype

JavaScript
// Масив: arr → Array.prototype → Object.prototype → null
const arr = [1, 2, 3];
console.log(Object.getPrototypeOf(arr) === Array.prototype);         // true
console.log(Object.getPrototypeOf(Array.prototype) === Object.prototype); // true

// arr.map — з Array.prototype
// arr.toString — з Object.prototype

// Рядок (autoboxing): str → String.prototype → Object.prototype
const str = 'hello';
// String.prototype.toUpperCase, slice, includes...

// Число: num → Number.prototype → Object.prototype
// Number.prototype.toFixed, toString...

// Функція: fn → Function.prototype → Object.prototype
// Function.prototype.call, apply, bind...

Поліфіли вбудованих методів

JavaScript
// Можна додати власний метод у вбудований prototype
// АЛЕ це небезпечна практика — уникайте у production!

if (!String.prototype.trimAll) {
  String.prototype.trimAll = function() {
    return this.replace(/\s+/g, ' ').trim();
  };
}
console.log('  hello   world  '.trimAll()); // "hello world"

// Проблеми полютованих прotototype:
// 1. Конфлікт з майбутніми стандартами (Array.prototype.flat так з'явився)
// 2. Конфлікт з іншими бібліотеками
// 3. for...in може підхопити додані методи

Запозичення методів

JavaScript
// Запозичення методу Array для array-like об'єктів
function joinArgs() {
  // arguments — array-like, але не масив
  return Array.prototype.join.call(arguments, ', ');
}
console.log(joinArgs(1, 2, 3)); // "1, 2, 3"

// Сучасний підхід — spread або Array.from
function joinArgs2(...args) { return args.join(', '); }

Підсумок

  • Всі об'єкти успадковують від Object.prototype. Масиви → Array.prototype → Object.prototype → null.
  • Методи на примітивах (рядках, числах) беруться з відповідних вбудованих прotototype через autoboxing.
  • Розширення вбудованих прotototype — погана практика (поліфіли є єдиним виправданим випадком).
