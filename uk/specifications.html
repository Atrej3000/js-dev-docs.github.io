Довідники і специфікації

Початковий Вступ ~ 8 хв

Для точних відповідей щодо поведінки мови існує ієрархія джерел. Уміння знайти потрібне джерело і правильно його прочитати — базова навичка будь-якого розробника.

Чому це важливо

Блоги, Stack Overflow і навчальні платформи — вторинні джерела. Вони можуть містити застарілу або неточну інформацію. Первинне джерело — специфікація ECMAScript і офіційна документація відповідного API. Звичка перевіряти первинні джерела відрізняє розробника, який знає, від того, хто лише думає, що знає.

Специфікація ECMAScript

ECMA-262 — офіційний стандарт мови JavaScript. Публікується організацією Ecma International, технічним комітетом TC39. Актуальна версія завжди доступна за адресою tc39.es/ecma262/.

Специфікація описує семантику мови: що саме повинен робити рушій у кожній ситуації. Вона не містить прикладів або пояснень для початківців — це нормативний документ для авторів рушіїв.

Пропозиції TC39

Нові функції мови проходять п'ять стадій (Stage 0–4) до включення у стандарт. Репозиторій усіх активних пропозицій: github.com/tc39/proposals.

СтадіяНазваЗначення
Stage 0StrawpersonІдея без формального розгляду
Stage 1ProposalПрийнято до розгляду, є чемпіон
Stage 2DraftЧорновик специфікації готовий
Stage 2.7RecommendedГотово до реалізації
Stage 3CandidateРеалізовано в рушіях, збір відгуків
Stage 4FinishedВключено в наступну версію стандарту
Stage 3 у продакшені

Stage 3 означає, що функція реалізована в сучасних рушіях і вважається стабільною за API. Більшість команд допускають Stage 3 у продакшені з відповідним polyfill для старих браузерів. Stage 4 — це гарантія включення в стандарт і повна стабільність.

MDN Web Docs

MDN Web Docs (developer.mozilla.org) — найповніший практичний довідник з JavaScript і браузерних API. Підтримується Mozilla у співпраці з Google, Microsoft та W3C.

Коли використовувати MDN:

  • Синтаксис методу або властивості
  • Параметри, повернуті значення, можливі винятки
  • Сумісність з браузерами (таблиця Browser Compatibility)
  • Стандарт, якому відповідає API (посилання на специфікацію)
  • Живі приклади коду з можливістю редагування
MDN як точка входу, spec — як кінцева відповідь

MDN дає швидку зрозумілу відповідь. Якщо відповідь критична (наприклад, точна поведінка при крайових значеннях), переходьте за посиланням на специфікацію з тієї ж сторінки MDN.

Can I Use

Can I Use (caniuse.com) — таблиці підтримки HTML, CSS і JavaScript API у браузерах з деталізацією по версіях. Незамінний інструмент перед використанням нового API в проекті з широкою цільовою аудиторією.

Для JavaScript-специфічних функцій таблиці сумісності прямо на сторінках MDN є більш детальними і актуальними.

Документація Node.js

API, специфічне для Node.js (fs, http, path тощо), описане у офіційній документації nodejs.org/api/. Документація прив'язана до конкретних версій Node.js — переконайтесь, що читаєте актуальну версію для вашого середовища.

Як читати специфікацію ECMAScript

Специфікація написана формальною нотацією. Для практичного використання достатньо розуміти кілька конструкцій:

  • Abstract Operations — внутрішні операції, які описують кроки виконання. Наприклад, ToNumber(argument) — алгоритм перетворення значення на число.
  • [[InternalSlot]] — внутрішній стан об'єкта, недоступний безпосередньо з коду. Наприклад, [[Prototype]] або [[Value]].
  • Completion Record — тип значення, що повертають внутрішні операції: normal, throw, return, break, continue.
Специфікація — для перевірки, не для навчання

Специфікація ECMAScript не є навчальним матеріалом. Починайте з MDN або цього курсу. Звертайтесь до специфікації, коли потрібна вичерпна точна відповідь щодо конкретної поведінки, яку неможливо знайти в документації.

Підсумок

  • Пропозиції TC39 на GitHub — спосіб відстежувати майбутнє мови.
  • MDN Web Docs — основний практичний довідник з API, синтаксису і сумісності.
  • Can I Use — таблиці браузерної підтримки для CSS/HTML/JS функцій.
  • Документація Node.js — для серверних API, прив'язана до версій.
  • Ієрархія: специфікація > MDN > блоги / Stack Overflow.
