Вступ до JavaScript

Початковий Вступ ~ 12 хв

JavaScript — мова програмування загального призначення з динамічною типізацією, яка первісно розроблялася для виконання в браузері. Сьогодні вона виконується у багатьох середовищах: від серверів до мікроконтролерів.

Чому це важливо

JavaScript — єдина мова програмування, яка виконується безпосередньо в браузері без компіляції чи плагінів. Розуміння її природи — не просто теоретична база: воно визначає, як і де виконується код, чому певні API доступні в одних середовищах і відсутні в інших, а також чому браузерний код не може читати файли операційної системи.

Що таке JavaScript

JavaScript вперше з'явився у 1995 році як скриптова мова для браузера Netscape Navigator. У 1997 році мову стандартизували під назвою ECMAScript (скорочено ES) — саме ця специфікація описує синтаксис, семантику і вбудовані об'єкти мови.

Назва «JavaScript» є зареєстрованою торговою маркою Oracle Corporation. Коректні технічні назви — ECMAScript або просто JS.

ECMAScript vs JavaScript

ECMAScript — специфікація мови. JavaScript — найпоширеніша її реалізація. Коли говорять «ES2024» або «ES15», мають на увазі конкретну версію стандарту ECMAScript. Нові версії виходять щороку у червні.

Як працює рушій JavaScript

Рушій (engine) — це програма, яка читає JS-код і виконує його. Рушій вбудований у браузер або середовище виконання.

Основні рушії:

  • V8 — Google Chrome, Microsoft Edge, Node.js, Deno, Bun
  • SpiderMonkey — Mozilla Firefox
  • JavaScriptCore (Nitro) — Safari, WebKit

Спрощений процес виконання коду рушієм V8:

  1. Парсинг. Рушій читає вихідний текст і будує AST — абстрактне синтаксичне дерево.
  2. Компіляція (JIT). V8 не інтерпретує AST рядок за рядком. Він компілює «гарячі» ділянки коду у нативний машинний код за допомогою Turbofan/Maglev. Це робить JavaScript значно швидшим від традиційної інтерпретації.
  3. Виконання. Скомпільований машинний код виконується на процесорі. V8 може перекомпілювати код повторно з урахуванням зібраної статистики типів.
  4. Garbage collection. Рушій автоматично звільняє пам'ять від значень, на які більше немає посилань (алгоритм mark-and-sweep).
JIT-компіляція

«JIT» (Just-In-Time) означає, що компіляція відбувається під час виконання, а не заздалегідь. Рушій аналізує, які функції викликаються часто, і компілює їх у машинний код. Решта коду може залишатись в інтерпретованому режимі.

Середовища виконання

Рушій — це лише мовне ядро. Для реальної роботи до нього приєднується середовище виконання (runtime), яке надає додаткові API.

Браузерне середовище

Браузер надає:

  • DOM API — маніпуляції з HTML-документом
  • BOM (Browser Object Model) — window, navigator, location, history
  • Web APIs — fetch, setTimeout, localStorage, WebSocket, Canvas, WebGL, Geolocation тощо
  • Event Loop — механізм обробки подій та асинхронних операцій

Жоден з цих об'єктів не є частиною специфікації ECMAScript. Це розширення конкретного середовища.

Node.js

Node.js — серверне середовище виконання на основі V8. Замість DOM та Web APIs воно надає:

  • модуль fs — робота з файловою системою
  • модуль http/https — HTTP сервер і клієнт
  • модуль path, os, crypto тощо
  • власну систему модулів (CommonJS та ESM)

Код, який звертається до document або window, не працюватиме в Node.js — ці об'єкти не існують у цьому середовищі.

JavaScript
// Середовище — браузер
console.log(typeof window);   // "object"
console.log(typeof document);  // "object"
console.log(typeof process);   // "undefined"

// Середовище — Node.js
console.log(typeof process);   // "object"
console.log(typeof window);    // "undefined"
console.log(typeof document);  // "undefined"

// Спільне для обох середовищ (ECMAScript core)
console.log(typeof Array);    // "function"
console.log(typeof Promise);  // "function"
console.log(typeof JSON);     // "object"

Обмеження безпеки браузера

Браузерний JavaScript виконується в пісочниці (sandbox) — ізольованому середовищі з суворими обмеженнями. Це свідомий дизайн: код із довільного веб-сайту не повинен мати доступ до ресурсів комп'ютера користувача.

Ключові обмеження:

  • Немає прямого доступу до файлової системи. JavaScript у браузері не може читати або записувати файли без явної дії користувача (наприклад, вибір файлу через <input type="file">).
  • Same-Origin Policy. Скрипт зі сторінки site-a.com не може читати відповіді з site-b.com без відповідних CORS-заголовків на стороні site-b.com.
  • Немає доступу до ОС. Неможливо виконати системну команду, прочитати реєстр Windows, відкрити сокет на довільному порту тощо.
  • Обмежений між-вкладковий доступ. Одна вкладка не може читати DOM іншої, якщо вони не з одного origin і не налаштовано явної комунікації (postMessage, SharedWorker тощо).
Браузер vs Node.js

Node.js не має цих обмежень: він може читати файли, виконувати системні команди, відкривати мережеві з'єднання. Саме тому серверний Node.js-код потребує уважного ставлення до введеного користувачем контенту.

JavaScript, HTML, CSS: ролі

Три технології браузера вирішують різні задачі і навмисно розділені між собою:

Технологія Роль Приклад
HTML Структура і вміст Заголовки, параграфи, форми, посилання
CSS Стиль і розташування Колір, шрифт, відступи, анімація
JavaScript Поведінка і взаємодія Обробка подій, зміна DOM, мережеві запити

JavaScript може динамічно змінювати і HTML, і CSS — але початковий документ завантажується без JS. Якщо рушій відключений або відбулася помилка, HTML і CSS залишаються видимими.

Що вміє JavaScript у браузері

  • Змінювати DOM: додавати, видаляти, змінювати HTML-елементи та їх атрибути
  • Реагувати на події: кліки, натискання клавіш, рухи миші, завантаження сторінки
  • Надсилати мережеві запити та отримувати відповіді (AJAX, Fetch API) без перезавантаження сторінки
  • Зберігати дані на стороні клієнта: localStorage, sessionStorage, IndexedDB, cookies
  • Малювати графіку через Canvas API та WebGL
  • Відтворювати аудіо і відео через Media API
  • Взаємодіяти з камерою і мікрофоном через MediaDevices API (з дозволу користувача)
  • Виконувати фонові операції через Web Workers

Унікальний статус мови

JavaScript є єдиною мовою, яка нативно підтримується усіма браузерами без плагінів чи додаткового ПЗ. Це надає їй особливе місце: будь-який пристрій із браузером є потенційним середовищем виконання.

Крім того, JavaScript — єдина мова, яка водночас є:

  • мовою для браузерних клієнтів (frontend)
  • повноцінною серверною мовою (Node.js, Deno, Bun)
  • мовою для мобільних застосунків (React Native, Ionic)
  • мовою для десктопних застосунків (Electron, Tauri)
  • мовою для хмарних функцій (Cloudflare Workers, AWS Lambda)
  • мовою для вбудованих систем (Espruino, Moddable SDK)

Мови, що компілюються у JavaScript

Для браузерного виконання будь-який код зрештою перетворюється на JavaScript. Це призвело до появи мов, які транспілюються у JS:

  • TypeScript — статична типізація поверх JavaScript. Компілятор tsc перетворює TS-код на JS.
  • CoffeeScript — лаконічний синтаксис, інспірований Python і Ruby. Сьогодні значно менш актуальний.
  • Dart — мова Google, основна для Flutter. Може компілюватись у JS для браузера.
  • Elm, ReasonML, PureScript — функціональні мови зі строгою типізацією, орієнтовані на браузер.

Знання JavaScript залишається необхідним для розуміння скомпільованого коду, налагодження і роботи зі стандартними браузерними API — навіть якщо повсякденна робота ведеться на TypeScript або іншому компільованому варіанті.

Підсумок

  • JavaScript — реалізація стандарту ECMAScript. Нові версії стандарту виходять щороку.
  • Рушій (V8, SpiderMonkey, JavaScriptCore) виконує JS через JIT-компіляцію — не інтерпретує рядок за рядком.
  • Браузер і Node.js — різні середовища. Вони додають різні API поверх спільного ядра ECMAScript.
  • Браузерний JS виконується в пісочниці: немає доступу до файлової системи, ОС, довільних мережевих з'єднань без обмежень Same-Origin Policy.
  • JavaScript — єдина мова нативної підтримки в браузерах. Усі альтернативи (TypeScript тощо) компілюються у JS.
  • Сфера застосування: браузер, сервер, мобільні, десктоп, хмарні функції, вбудовані системи.
