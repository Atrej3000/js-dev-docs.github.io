Змінні

Початковий Основи JavaScript ~ 18 хв

Змінна — це іменоване місце у пам'яті, що містить значення. У JavaScript змінна є прив'язкою імені до значення в межах конкретного лексичного середовища (lexical environment).

Чому це важливо

Вибір між var, let і const визначає не лише синтаксис, а й:

  • яка частина коду може читати змінну (область видимості);
  • чи можна перезаписати прив'язку (мутабельність);
  • коли змінна стає доступною під час виконання (hoisting / TDZ);
  • як замикання захоплюють значення в циклах;
  • чи забруднює змінна глобальний об'єкт globalThis.

Неправильний вибір ключового слова є джерелом класу багів, які важко відтворити і легко внести непомітно.

Ключові слова: var, let, const

Специфікація ECMAScript визначає три способи оголошення змінних. Кожен відрізняється за трьома осями: область видимості, hoisting і можливість переприсвоєння.

var — функціональна область видимості

Оголошення var створює прив'язку в найближчому function scope (або глобальному, якщо поза функцією). Блоки if, for, while не створюють нового scope для var.

JavaScript
function processData() {
  if (true) {
    var result = 42;   // не блоковий scope — видима у всій функції
  }
  console.log(result); // 42 — витікає з блоку if
}

processData();
console.log(typeof result); // "undefined" — за межами функції недоступна

var у глобальному контексті стає властивістю globalThis (у браузері — window):

JavaScript
var appName = 'Dashboard';
console.log(globalThis.appName); // "Dashboard" — забруднення глобального об'єкту

let version = '1.0';
console.log(globalThis.version); // undefined — let/const не торкаються globalThis

let — блокова область видимості

let обмежує прив'язку найближчим block scope ({ }): тіло функції, блок if, цикл, просто парні фігурні дужки. Переприсвоєння дозволено.

JavaScript
function processItems(items) {
  for (let i = 0; i < items.length; i++) {
    let current = items[i];  // нова прив'язка на кожній ітерації
    // current і i недоступні поза циклом
  }
  // console.log(i);      // ReferenceError
  // console.log(current); // ReferenceError
}

let counter = 0;
counter = 1;   // переприсвоєння дозволено
counter = 2;   // дозволено

const — незмінна прив'язка

const — блокова область видимості, як let, але прив'язка не може бути переприсвоєна після ініціалізації. Це не означає, що значення незмінне — об'єкт або масив можна мутувати.

JavaScript
const MAX_RETRIES = 3;
// MAX_RETRIES = 5; // TypeError: Assignment to constant variable

const config = { timeout: 5000, retries: 3 };
config.timeout = 10000; // OK — мутація об'єкту дозволена
// config = {};          // TypeError — переприсвоєння заборонено

const tags = ['api', 'auth'];
tags.push('cache');  // OK — масив мутується
// tags = [];           // TypeError
Семантика const

const гарантує незмінність прив'язки, а не незмінність значення. Для дійсно незмінних об'єктів використовуйте Object.freeze(). Заморожування поверхневе — вкладені об'єкти залишаються мутабельними.

Hoisting: підйом оголошень

Під час компіляції фази (перед виконанням) рушій JavaScript сканує поточне лексичне середовище і реєструє всі оголошення. Цей процес називають hoisting (підйомом). Поведінка різниться для var, let/const і функцій.

var hoisting

Оголошення var піднімається і ініціалізується значенням undefined ще до виконання коду. Присвоєння залишається на місці.

JavaScript
// Що пише розробник:
console.log(status); // undefined — не ReferenceError
var status = 'active';
console.log(status); // "active"

// Як рушій інтерпретує (спрощена модель):
var status;          // підйом: ініціалізація → undefined
console.log(status); // undefined
status = 'active';   // присвоєння на місці
console.log(status); // "active"

let та const: Temporal Dead Zone (TDZ)

let і const також піднімаються (їх прив'язки реєструються в середовищі під час компіляції), але не ініціалізуються. Від початку блоку до рядка оголошення змінна перебуває в Temporal Dead Zone. Будь-яке звернення в TDZ — ReferenceError.

JavaScript
// TDZ починається на початку блоку

{
  // ← TDZ для `value` починається тут
  console.log(typeof value); // ReferenceError — TDZ активна
  // (увага: typeof не рятує від TDZ для let/const)

  let value = 10;            // ← TDZ для `value` закінчується тут
  console.log(value);        // 10
}

// Практичний наслідок:
function getDefault() { return 42; }

const config = {
  // timeout: timeout, // ReferenceError — TDZ
  timeout: 5000,
};

let timeout = config.timeout ?? getDefault();
console.log(timeout); // 5000
typeof і TDZ

До ES6 вираз typeof undeclaredVar повертав "undefined" без помилки. Це більше не безпечно: typeof кидає ReferenceError, якщо ім'я прив'язане до let/const у TDZ. Не покладайтесь на typeof для перевірки існування let/const змінних.

Hoisting оголошень функцій

Function declarations піднімаються повністю — разом з тілом. Їх можна викликати до рядка оголошення. Function expressions (const fn = function() {}) підпорядковані правилам відповідного ключового слова.

JavaScript
// Function declaration — повний підйом
console.log(square(4)); // 16 — виклик до оголошення

function square(n) {
  return n * n;
}

// Function expression — підпорядкована let/const
console.log(typeof cube); // ReferenceError — TDZ

const cube = function(n) {
  return n * n * n;
};

Область видимості на практиці

Блок як одиниця ізоляції

JavaScript
// Явна ізоляція через блок без функції
{
  const requestId = crypto.randomUUID();
  const payload   = buildPayload(requestId);
  await sendRequest(payload);
  // requestId і payload недоступні поза блоком
}

// Умовна ізоляція
let response;

if (isAuthenticated) {
  const token = generateToken(user);  // видима тільки в if-блоці
  response = await fetch('/api/data', {
    headers: { Authorization: `Bearer ${token}` }
  });
} else {
  response = await fetch('/api/public');
}

// token тут недоступний — це навмисно

Вкладені scope та shadowing

Внутрішній scope може оголосити змінну з тим самим ім'ям, що і зовнішній — це називається shadowing (тінення). Зовнішня прив'язка не змінюється.

JavaScript
const limit = 100;

function applyUserLimit(userLimit) {
  const limit = Math.min(userLimit, 50); // тінить зовнішній `limit`
  return limit;
}

console.log(applyUserLimit(80)); // 50
console.log(limit);              // 100 — зовнішній не змінився

// Shadowing var ← let: легальне, але потенційно заплутане
var count = 1;
{
  let count = 2;         // тінить var count у цьому блоці
  console.log(count);    // 2
}
console.log(count);      // 1

Змінні в циклах: класична пастка

Одна з найвідоміших проблем із var — відсутність нової прив'язки на кожній ітерації циклу. Всі замикання, створені в тілі циклу, посилаються на одну і ту саму змінну.

JavaScript
// АНТИПАТЕРН: var у циклі з асинхронним колбеком
const handlers = [];

for (var i = 0; i < 3; i++) {
  handlers.push(function() { return i; });
  // всі функції замикають одну прив'язку `i`
}

console.log(handlers[0]()); // 3 — не 0
console.log(handlers[1]()); // 3 — не 1
console.log(handlers[2]()); // 3 — не 2
// До моменту виклику цикл завершився: i === 3

// РІШЕННЯ 1: let — окрема прив'язка на кожну ітерацію
const handlersFixed = [];

for (let j = 0; j < 3; j++) {
  handlersFixed.push(function() { return j; });
  // кожна ітерація — нове лексичне середовище з новим `j`
}

console.log(handlersFixed[0]()); // 0
console.log(handlersFixed[1]()); // 1
console.log(handlersFixed[2]()); // 2

// РІШЕННЯ 2 (legacy): IIFE для явного захоплення
const handlersIIFE = [];

for (var k = 0; k < 3; k++) {
  handlersIIFE.push((function(captured) {
    return function() { return captured; };
  })(k));
}

console.log(handlersIIFE[0]()); // 0
Механіка let у циклі

Специфікація ECMAScript (розділ 14.7.4) визначає: на кожній ітерації циклу for з let/const рушій створює нове лексичне середовище і копіює поточні значення прив'язок. Ефект аналогічний IIFE, але без синтаксичного шуму.

Edge Cases

Повторне оголошення

JavaScript
// var: повторне оголошення в тому самому scope — мовчазне ігнорування
var status = 'active';
var status = 'pending'; // не помилка — просто переприсвоєння
console.log(status);    // "pending"

// let: повторне оголошення в тому самому scope — SyntaxError
let count = 0;
// let count = 1; // SyntaxError: Identifier 'count' has already been declared

// В різних scope — OK
let value = 'outer';
{
  let value = 'inner'; // нова прив'язка — не помилка
  console.log(value);  // "inner"
}
console.log(value);    // "outer"

const та Object.freeze

JavaScript
// Поверхневе заморожування
const config = Object.freeze({
  host: 'localhost',
  db: { port: 5432 }  // вкладений об'єкт НЕ заморожений
});

// config.host = 'prod'; // TypeError у strict mode, мовчки в sloppy
config.db.port = 3306;   // OK — глибоке заморожування потрібно окремо
console.log(config.db.port); // 3306

// Глибоке заморожування (рекурсивна утиліта):
function deepFreeze(obj) {
  Object.getOwnPropertyNames(obj).forEach(name => {
    const value = obj[name];
    if (value && typeof value === 'object') deepFreeze(value);
  });
  return Object.freeze(obj);
}

const settings = deepFreeze({ db: { port: 5432 } });
// settings.db.port = 9999; // TypeError

Спільний scope у switch

Усі case-блоки в switch розділяють одне лексичне середовище. Оголошення let/const в одному case видиме у всьому switch:

JavaScript
// ПРОБЛЕМА: спільний scope без фігурних дужок
switch (status) {
  case 'active':
    let message = 'User is active';
    break;
  case 'inactive':
    // let message = 'User is inactive'; // SyntaxError: вже оголошена вище
    break;
}

// РІШЕННЯ: ізолювати кожен case власним блоком
switch (status) {
  case 'active': {
    const message = 'User is active';
    console.log(message);
    break;
  }
  case 'inactive': {
    const message = 'User is inactive'; // OK — окремий scope
    console.log(message);
    break;
  }
}

Антипатерни та поширені помилки

1. Витік var у глобальний scope

JavaScript
// АНТИПАТЕРН: var на верхньому рівні модуля
var userId = null; // стає window.userId у браузері

// КРАЩЕ: let або const
let userId = null;  // не потрапляє в globalThis

2. Використання const без ініціалізації

JavaScript
// SyntaxError: Missing initializer in const declaration
// const MAX;       // не компілюється

const MAX = 100;    // завжди потрібна ініціалізація

3. TDZ у методах класу

JavaScript
// Небезпечний виклик через TDZ з class expressions
const instance = new MyService(); // ReferenceError якщо клас оголошено нижче
                                  // через class expression (не declaration)

// class declaration: повний підйом тіла — виклик зверху безпечний
class MyService {
  process() { return 'ok'; }
}

// class expression: підпорядкована TDZ
// const MyService = class { ... }; // НЕ піднімається

4. var у for…in / for…of

JavaScript
const data = { a: 1, b: 2, c: 3 };

// АНТИПАТЕРН
for (var key in data) { /* key потрапляє у function scope або глобальний */ }
console.log(key); // "c" — витік змінної циклу

// ПРАВИЛЬНО
for (const key in data) {
  // key обмежений тілом циклу
}
// console.log(key); // ReferenceError

Найкращі практики

1. const за замовчуванням

Починайте кожне оголошення з const. Переходьте до let лише коли необхідне переприсвоєння. Це комунікує намір читачу коду: «це значення не змінюється в межах свого scope».

JavaScript
// Правило: const → let → (ніколи) var
const BASE_URL    = '/api/v2';
const maxRetries  = 3;

let currentPage   = 1;  // змінюється при пагінації
let isLoading     = false;

// Для накопичення в циклі — let
let total = 0;
for (const item of cart) {
  total += item.price;
}

2. Мінімізуйте scope

Оголошуйте змінну якомога ближче до місця використання і в мінімально необхідному scope. Це зменшує когнітивне навантаження і ризик побічних ефектів.

JavaScript
// ГІРШЕ: оголошення на початку функції (стиль var-ери)
function processOrder(order) {
  let itemCount;
  let discount;
  let total;
  // ... 30 рядків логіки ...
  itemCount = order.items.length;
  // ...
}

// КРАЩЕ: оголошення біля використання
function processOrder(order) {
  // ...
  const itemCount = order.items.length;
  const discount  = itemCount > 5 ? 0.1 : 0;
  const total     = order.items.reduce((sum, item) => sum + item.price, 0);
  return total * (1 - discount);
}

3. Описові імена, без скорочень

JavaScript
// АНТИПАТЕРН: однолітерні або скорочені імена поза межами ітераторів
const u = getUser();
const d = u.data;
const t = d.timestamp;

// КРАЩЕ: самодокументований код
const user            = getUser();
const profileData     = user.data;
const lastSeenAt      = profileData.timestamp;

// Виняток: i, j, k, x, y — прийнятні для ітераторів і математики
for (let i = 0; i < items.length; i++) { /* ... */ }
const distance = Math.sqrt(x * x + y * y);

4. Не використовуйте var у новому коді

var не має жодної переваги над let у сучасному JavaScript. Функціональний scope можна отримати через функцію, а глобальні прив'язки — через явне присвоєння globalThis.name = value (у тих рідкісних випадках, коли це справді потрібно).

Ментальна модель

Уявіть лексичне середовище як таблицю прив'язок: ключ — ім'я, значення — поточний вміст. При вході в блок (функцію, if, цикл) рушій створює нову таблицю з посиланням на зовнішню. Пошук імені йде з поточної таблиці вгору по ланцюгу до глобальної.

  • var — запис у таблицю функції (або глобальній), ігноруючи блоки.
  • let/const — запис у таблицю поточного блоку.
  • TDZ — рядок у таблиці існує, але позначений як «не ініціалізований»: читання = помилка.
  • Замикання — функція зберігає посилання на таблицю середовища, де була створена.

Підсумок

  • var — функціональна область видимості, hoisting з ініціалізацією undefined, забруднює globalThis. Уникайте у новому коді.
  • let — блокова область видимості, TDZ, переприсвоєння дозволено.
  • const — блокова область видимості, TDZ, переприсвоєння заборонено. Не гарантує незмінність об'єкту.
  • TDZ: let/const реєструються під час компіляції, але не ініціалізуються до рядка оголошення. Звернення в TDZ — ReferenceError.
  • typeof в TDZ кидає ReferenceError — на відміну від неоголошених змінних.
  • Цикл for з let — нова прив'язка на кожну ітерацію: замикання захоплюють різні значення.
  • switch: усі case розділяють один scope — ізолюйте блоками { }.
  • Стратегія за замовчуванням: const → let → var тільки для legacy-коду.
